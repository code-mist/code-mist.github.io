Common File Signatures You Must Know

必须记住的文件签名

在网络安全、恶意软件分析和数字取证的世界里，有一个最基础、也最容易被忽视的真相：你看到的文件扩展名，可能一直在撒谎。

一个名为 invoice.pdf 的文件，双击打开后可能不是一份账单，而是一个瞬间接管你系统的恶意程序。一个伪装成 .jpg 的图片文件，背后可能藏着勒索软件的加密模块。

而在数字世界，唯一能揭穿这些谎言、看清文件“真面目”的，就是文件最开头的几个字节——文件签名（File Signature） ，也被称为魔数（Magic Number） 。

一、什么是文件签名？为什么它是安全分析的第一道防线？

文件签名是文件开头用来标识其真实类型的一段特定的十六进制字节序列。操作系统和软件在打开文件时，理论上应该先读取这几个字节，而不是盲目相信文件名后面的 .pdf 或 .jpg。

然而，扩展名可以被随意重命名，但文件签名很难被轻易伪造。攻击者非常清楚这一点，因此他们最常用的技术之一就是“文件类型伪装”：修改恶意文件的扩展名，或者直接编辑文件头的十六进制代码，来绕过基于扩展名的简单过滤和用户的第一眼判断。

有攻击者曾将可执行文件伪装成 .txt 文本文档来投递恶意软件。甚至有 PHP 后门被命名为 test.gif，利用用户对图片文件的天然信任来降低警惕。

这就是为什么每一位安全从业者都必须把最常见的文件签名刻在脑子里。

二、安全人必须“刻在 DNA 里”的文件签名清单

下面这份清单，是你在恶意软件分析、应急响应和渗透测试中最高频遇到的“嫌疑人档案”。

🧬 可执行文件：最危险的伪装者

Windows PE（Portable Executable）：4D 5A 这是所有 .exe、.dll、.sys 文件的开头。4D 5A 转换成 ASCII 就是 “MZ” ，这是 MS-DOS 核心开发者 Mark Zbikowski 的姓名首字母缩写。这个签名从 1980 年代的 DOS 时代一直沿用至今，现代 Windows 程序为了向后兼容，依然保留着这个“签名”。关键场景：如果一个声称是 .pdf 或 .jpg 的文件，开头却是 4D 5A，它本质上就是一个 Windows 可执行文件，应立即被视为可疑对象。

Linux ELF（Executable and Linkable Format）：7F 45 4C 46 第一个字节 7F 之后紧跟 ASCII 的 “ELF” 。这是 Linux/Unix 系统下的可执行文件、共享库和核心转储的标准签名。

🖼️ 图像文件：藏污纳垢的常见载体

JPEG：FF D8 FF 最常见的图片格式之一，文件结尾通常是 FF D9。攻击者常利用图片文件进行隐写术，将恶意代码隐藏在大片像素数据中。

PNG：89 50 4E 47 0D 0A 1A 0A 这个签名非常独特，包含了多个非打印字符，50 4E 47 在 ASCII 中正是 “PNG” 。其复杂性使其极难被误判，但依然常被用来制作伪装的恶意文件。

GIF：47 49 46 38 ASCII 对应 “GIF8” ，后面紧跟的通常是 37 61（GIF87a）或 39 61（GIF89a）。恶意广告中常利用 GIF 来投递载荷。

📄 文档文件：钓鱼攻击的“主战场”

PDF：25 50 44 46 2D ASCII 对应 %PDF- ，后面通常跟着版本号（如 1.4）。恶意 PDF 是钓鱼邮件和“路过式下载”攻击中最常见的载体之一。

现代 Microsoft Office（DOCX/XLSX/PPTX）：50 4B 03 04 这是最容易被误解的签名之一。.docx 本质上是一个包含 XML 文件的 ZIP 压缩包。50 4B 在 ASCII 中是 “PK” ，代表 ZIP 格式的创造者 Phil Katz 。因此，恶意宏或嵌入式脚本可以轻松地藏在这个“压缩包”里。

旧版 Microsoft Office（DOC/XLS）：D0 CF 11 E0 A1 B1 1A E1 这是经典的“复合文件二进制格式”（Compound File Binary Format）签名，老式 Office 文档以及部分 MSI 安装包都在使用。

🗜️ 压缩包：批量投递的“集装箱”

ZIP：50 4B 03 04 （同样适用于 JAR、APK 等基于 ZIP 的格式）

RAR：52 61 72 21 ASCII 对应 “Rar!” ，RAR 5.0 之后紧跟 1A 07。

7-Zip：37 7A BC AF 27 1C

GZIP：1F 8B

🎬 音视频文件：不可忽视的攻击面

MP4：00 00 00 18 66 74 79 70 其中包含 ASCII 的 “ftyp” 。MP4 文件的结构化程度较高，但也存在被利用来封装恶意载荷的可能。

AVI：52 49 46 46 （ASCII “RIFF” ），随后是 41 56 49 20（“AVI ”）。

MP3：49 44 33 （ASCII “ID3” ），表示带有 ID3v2 元数据。也可以是 FF FB（原始 MP3 帧）。

WAV：52 49 46 46 （“RIFF”），随后是 57 41 56 45（“WAVE”）。

三、进阶威胁：当文件签名本身被武器化

仅仅记住签名还不够。攻击者的手段早已超越了简单的扩展名修改。

多语言文件（Polyglot Files） 是一种更高级的伪装形式。一个文件可以同时符合两种或多种文件格式的规范，根据打开它的应用程序不同，表现出不同的行为。例如，一个文件既可以作为合法的 PDF 被阅读器正常打开，又可以作为一个可执行载荷被特定程序执行。这种文件专门用于欺骗那些“根据文件类型路由到不同检测器”的安全系统。

此外，代码签名滥用也是一个严峻的现实。攻击者通过窃取或伪造的数字证书为恶意软件签名，使其披上“可信”的外衣，从而绕过基于信誉和白名单的防御体系。这提醒我们，“已签名”不等于“安全” ，行为检测比签名验证更为根本。

四、你的武器库：如何查看和验证文件签名？

你不需要成为逆向工程大师，只需要几个基础工具就能完成第一轮排查。

十六进制编辑器是查看文件原始字节的必备工具。推荐 HxD（Windows，免费）、010 Editor（跨平台，商业但功能强大）、Hex Fiend（macOS，免费）。用它们打开任何可疑文件，直接看前几个字节是否符合其扩展名应有的签名。

自动化识别工具可以帮你快速判断。Linux 下的 file 命令是经典之选。TrID 则是一个更强大的文件类型识别工具，内置了近两万种文件类型的模式定义，能以命令行的方式给出多个可能的匹配结果，非常适合批量扫描和应急响应。此外，FileShield 等专注于恶意文件类型检测的工具也值得关注。

对于 Windows PE 文件，PEStudio、CFF Explorer 等工具可以进一步解析文件头结构，帮助判断其是否包含可疑的节区或导入表。

五、防御的核心逻辑：永远不要相信扩展名

文件签名之所以重要，是因为它揭示了一个基本的安全原则：验证内容，而不是信任标签。

在应急响应中，当你发现一个名为 report.pdf 的文件，用十六进制编辑器打开后，前两个字节是 4D 5A，你应该立刻停止任何基于“这是一个 PDF”的假设。它是一个 Windows 可执行文件，需要按照 PE 恶意软件的流程进行处理。

同样，当一个 .docx 文件的行为异常时，记住它的本质是一个 ZIP 压缩包，你可以将其重命名为 .zip 来检查内部是否包含了可疑的宏脚本或嵌入式可执行文件。

对于企业防御而言，在文件上传、邮件附件过滤等环节部署基于魔数的严格校验，而不是依赖扩展名，是阻断大量低级伪装攻击的有效手段。

写在最后

文件签名是数字世界里的“防伪标识”。它不会说谎，但需要你懂得如何读取它。

记住那些最危险的数字：4D 5A 是披着羊皮的狼，50 4B 里可能藏着文档炸弹，25 50 44 46 的平静水面下也可能暗流涌动。

在安全这场攻防战中，攻击者在不断学习如何伪装，而防御者的第一课，永远是看清事物的本质。
